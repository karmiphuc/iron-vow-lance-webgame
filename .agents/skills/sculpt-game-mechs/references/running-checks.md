# Reproducible sculpt review

Choose an image check when comparing a reference to a sculpt. For repeated Blender revisions with named rig pivots, also use the [rig geometry check](rig-check.md). A photograph can show armor placement over a joint whose center is invisible.

## Set up once for a disputed view

1. The reviewer chooses the exact source view, camera/pose, anatomical side, height anchors, and the specific edges, pivot centers or small features to inspect. Define each landmark so a second reader can mark the same place on a clean image. Include a neighboring feature that should stay put. Use a separate contract for each view. For torso and limb proportions choose a fixed body landmark. A stowed cannon can still bias every ratio if the barrel itself is too long. When scale or stance is uncertain, add an independent fixed body edge or a pose landmark whose relationship should already agree. Define its usual numerical check and list its ID in the contract’s optional `alignment_checks`. Use controls whose stability is established. A guard taken from the disputed part could mask the very change under review. If any control misses its tolerance, the checker retains the raw readings and defers dimensional judgments to REVIEW. For a side-specific detail whose visibility depends on that view, set `"requires_alignment": true` on its count. That count also goes to REVIEW when a control misses. A count can stand on its own when its entire inspection region is identifiable in both images.
2. Copy the structure of the [Husky contract](../examples/husky-front.contract.json). Record source native pixels, dimensions and image SHA-256. For every required check choose its allowable deviation **before evaluating the revision**. Use prior accepted frames, the intended scale, or the owner's direction to set tolerances. Husky’s three-percentage-point window is an example review setting. Capture the contract digest with the task or review record and give it to the verifier separately from the artist's submission.
3. The artist returns the exact matched render and a [candidate observation](../examples/husky-front.candidate.json). Use native image coordinates with the origin at the top left. Mark a point as `[x,y]`, an obscured feature as `null`, and an inspected region with zero occurrences as `[]`. For counts, mark each feature center. Define separate checks for distinct shapes when identity matters. Estimate `error_px` from the least certain visible edge used in that observation. For a hidden or badly foreshortened axis, use `null` and obtain another view.

Both observations use the contract's view string. The checker uses FFmpeg on PATH to decode the first frame of each PNG or JPEG and apply display orientation. Record pixel coordinates and dimensions as they appear after orientation. The overlay embeds that decoded frame, and the report pins the original file bytes. A missing decoder or unreadable image returns ERROR. An image path may be absolute or relative to the JSON containing it. On another machine, create a local contract pointing at the private reference and record its new digest. Keep private source images and the embedded review HTML with the working assets.

## Run the check

From the skill directory, the following optional replay uses the archived Husky images. Put the authorized originals in the ignored `examples/private/` directory as `reference-front.jpg` and `Husky Front.jpg`. The portable regression suite generates its own images. Its expected exit is **1** because there are real differences. For a new task, substitute the task's independently recorded contract digest and the digest of the actual delivered render.

```sh
python3 scripts/check_proportions.py examples/husky-front.contract.json examples/husky-front.candidate.json --contract-sha256 1d0fae766c5b9cf40f43e554611e03d81bf7b06a02babc6cb14a37a79e4e70f2 --candidate-image-sha256 8a813ad34b0eb9d2c8383113c1401dee4b0ec87f071ad5e710644b64109a208f --repeat examples/husky-front.repeat.json --overlay examples/private/husky-front-check.html
```

Read stdout as JSON. For each check it reports reference, candidate, signed difference (candidate minus reference), conservative difference interval, and outcome. `height` measures a point above the sole. `span` measures projected distance between two points. `gap` measures the signed vertical displacement from point one to point two. For an asymmetric front or rear view, choose one fixed centerline mark and one identifiable fixed mark on a named side. `xgap` measures the signed horizontal distance from the first to the second, positive to the viewer’s right. Add its check ID to `alignment_checks` when a mirrored image could change the conclusion. Set its tolerance from the accepted view, small enough to distinguish the two sides. The height anchors by themselves cannot verify scale or handedness. These values are percentages of each subject’s marked height. Tolerances are percentage points. `count` compares the exact number of annotated features of one defined type.

| Exit | What the checking agent returns |
| --- | --- |
| 0 · PASS | The declared checks fit their tolerances. Inspect the overlay to verify camera, named edges, feature identity and pose before reporting a pass for this view. |
| 1 · FAIL | Report each failed check with signed difference and interval. Include any REVIEW rows. Return the marked view to the artist. |
| 2 · ERROR | Evidence or input is invalid. Regenerate the mismatched file or fix the malformed observation before judging the sculpt. |
| 3 · REVIEW | The uncertainty overlaps a limit, or a required landmark is hidden. Identify the unresolved check and the view or closer crop needed to resolve it. |

When the owner keeps flagging a region, give a second agent the clean images and landmark definitions first. Have it mark them without seeing the artist's coordinates or verdict. Supply the two independent observations together with `--repeat`, as in the example. The image digests must identify the same reference and delivered render. The script retains both readings and flags disputed verdicts or placements for REVIEW. On each individual image it pairs feature centers one-to-one, regardless of order, within the two readers’ combined pixel uncertainty on each axis. For pivots used in a span it compares both coordinates. For a horizontal or vertical edge measurement it checks the relevant axis. Independently marking the same quantity on different plates now exposes the disagreement. Both readers can still misidentify the same part. Inspect the overlay against the named pocket or edge. If one reader would pass a feature and another would fail or defer it, report the disagreement and refine the feature definition, pose, or view. Keep the original signed contract as review history when replacing an ambiguous definition. An image digest identifies bytes. A matching camera label alone cannot establish pose alignment, and a feature count depends on what the reviewer actually marked.

The archived Husky trial demonstrates why this matters. Two readers measured the apron about 5.5 and 5.7 percentage points lower. Both found the two absent slot shapes. Their cuff readings straddled the tolerance boundary, and the wrist pivot was hidden. Leave both the cuff and forearm length for further review.

On Giza, using a stowed cannon tip as the top anchor made the hand look 7.4 percentage points too low. Using the fixed cockpit roof yielded 4.1 points with an uncertainty interval crossing the tolerance. The apparent apron difference even reversed direction. A verifier should return that view for better registration and pose matching before recommending a limb edit.

For handoff, include contract and render digests, exit code, JSON report, and the overlay. Give each required view and geometry check its own result. Only report overall dimensional clearance once all required checks pass and landmark placement has been audited. The owner judges the finished look at Workshop and battle scale.


Run `python3 scripts/test_proportions.py` after changing the checker. The suite covers a reflected asymmetric fixture, reordered fasteners, displaced pivots, corrupt pixels, an EXIF-rotated JPEG and the existing proportion cases.
